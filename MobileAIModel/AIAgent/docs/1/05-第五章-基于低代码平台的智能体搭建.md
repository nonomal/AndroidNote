# 第五章 基于低代码平台的智能体搭建

## 一句话总结

低代码平台就是"智能体界的乐高":不写代码(或只写一点点),靠拖拽节点、连连线、填提示词,几十分钟就能搭出一个能用的智能体。这一章带你把 Coze、Dify、FastGPT、n8n 四大平台各搭一个真实案例,更重要的是搞清楚:**什么时候该拖拽,什么时候必须写代码**。

## 本章你能学到什么

- 低代码平台解决了什么痛点,四大主流平台各自的性格
- 四个完整实操:每日 AI 简报(Coze)、个人超级助手(Dify)、智能投顾(FastGPT)、智能邮件助手(n8n)
- 一套写"结构化提示词"的模板(Profile/Skills/Rules/Workflows),写代码时同样好用
- 选型决策框架:业务方、独立开发者、企业各该用什么

> 本章是全书少有的"不用敲代码"章节,但**不等于不用动手**——四个案例至少亲手搭一个,拖拽的手感和写代码的手感差异,只有亲手体验过才有发言权。

---

## 一、为什么会有低代码平台

前四章你已经体会到:哪怕一个最简单的智能体,也要管密钥、装依赖、写循环、处理解析失败。对程序员这是基本功,但对产品经理、运营、业务专家来说是一堵墙。低代码平台把这堵墙拆了:

- **可视化编排**:把"感知→思考→行动"的循环画成流程图,节点=步骤,连线=数据流向;
- **开箱即用的组件**:LLM 节点、知识库节点、搜索插件、定时触发器……全是现成积木;
- **托管运行**:不用买服务器、不用管部署,搭完直接发布成网页/机器人。

代价也明摆着:**灵活性天花板低**(平台没提供的能力你就是做不到)、**深度调试难**(出错时看不到底层日志)、**被平台绑定**(搬家成本高)。这个权衡贯穿全章。

## 二、四大平台的性格速写

| 平台 | 一句话性格 | 最适合 |
|---|---|---|
| **Coze(扣子)** | 字节出品,插件生态最丰富,离 C 端发布最近(一键发到飞书/微信) | 想快速做个对话机器人给别人用 |
| **Dify** | 开源可私有化部署,工程味最浓,API 友好 | 企业内部署、要和自己系统集成 |
| **FastGPT** | 知识库问答是看家本领,检索配置粒度细 | 客服/文档问答类场景 |
| **n8n** | 本质是自动化工作流工具(先有 workflow 后有 AI),节点连万物 | 要和邮件、日历、数据库等一堆外部系统打通 |

## 三、实操案例一:Coze 搭"每日 AI 简报"助手

**目标**:每天自动搜集 AI 新闻、论文、开源项目,生成一份格式固定的简报。

动手路径(在 [coze.cn](https://www.coze.cn) 注册后):

1. **建 Bot**:工作空间 → 创建 Bot,填名称和人设提示词("你是AI资讯编辑,每天输出一份简报……");
2. **搭工作流(Workflow)**:这是核心。新建工作流,依次拖入并连线:
   - **开始节点**(接收触发) → **插件节点×3**(必应搜索/头条搜索,分别搜"AI新闻""AI论文""AI开源项目") → **LLM 节点**(把三路搜索结果汇总,按固定模板改写成简报) → **结束节点**(输出);
3. **定格式**:在 LLM 节点的提示词里写死输出模板(🚀 AI技术新闻 / 📚 AI学术论文 / 💻 AI开源项目 三个栏目,每条带链接)——这一步的本质就是第三章讲的"给格式和边界";
4. **加定时**:触发器设为每天早上 8 点自动跑;
5. **发布**:一键发布到豆包/飞书/微信公众号。

**验收标准**:手动试运行一次,能收到三栏齐全、格式稳定的简报。

**这个案例的知识点迁移**:你搭的这条"多路搜索→汇总改写"流水线,和 docs/2 第 13 篇手敲的深度研究智能体是**同一个架构**(并行搜集+汇总生成),一个用拖拽实现,一个用 Python 实现。对照着看,架构思维就打通了。

## 四、实操案例二:Dify 搭"超级个人助手"

**目标**:一个既能闲聊、又能查天气、还能读你上传文档的多面手助手。

Dify 有两种用法:官方云版([dify.ai](https://dify.ai))直接注册,或用 Docker 在自己电脑私有化部署(`docker compose up -d`,Docker 怎么用见 docs/2 第 8 篇)。动手路径:

1. **建应用**:选 "Agent" 类型;
2. **写结构化提示词**:这是本案例的精华。原书用了一套很值得抄的模板:
   - **Profile(人设)**:你是谁、什么语气;
   - **Skills(技能)**:你会做哪几类事(查询、总结、翻译……);
   - **Rules(规则)**:什么坚决不做、遇到不确定怎么办;
   - **Workflows(流程)**:接到请求后按什么顺序处理;
   - **Initialization(开场)**:第一句话说什么。
3. **挂工具**:在工具面板勾选天气查询、网页搜索等内置工具;
4. **挂知识库**:上传几个 PDF/Word,Dify 自动切块、向量化(原理见第八章),对话时自动检索引用;
5. **调试与发布**:右侧对话框实时测试,满意后发布为网页或 API。

**验收标准**:同一个助手,能接住三种问题——闲聊("今天心情不好")、工具题("北京天气如何")、文档题("我上传的合同里违约金是多少")。

> 这套 Profile/Skills/Rules/Workflows 模板**不是 Dify 专属**——你写代码时的系统提示词照抄这个骨架,质量立涨一截。docs/2 第 11 篇 MiniAgent 的系统提示词其实就是它的简化版。

## 五、实操案例三与四:FastGPT 投顾助手、n8n 邮件助手(概览)

**FastGPT("智能投顾助手")**:核心是把一批金融知识文档灌进知识库,重点体验它比别家细的检索配置——切块大小、相似度阈值、召回条数都能调。你会直观看到:**同样的文档,检索参数不同,回答质量天差地别**(这正是第八章 RAG 调优的预习)。

**n8n("智能邮件助手")**:核心是"AI 只是流程中的一个节点"。搭一条流水线:**收到新邮件(Gmail 触发器)→ LLM 节点判断意图并起草回复 → 存入草稿箱/发送**。再进一步,把公司 FAQ 存成向量库节点,LLM 回复前先检索——一个带私有知识库的自动客服就成了。n8n 的启示:**智能体不一定是"聊天框",它可以是任何自动化流程里的一颗智能螺丝**。

这两个案例按原书或平台官方文档步骤操作即可,遇到界面改版就以官方文档为准(低代码平台界面迭代很快,记流程思路,别记按钮位置)。

## 六、拖拽还是写代码?选型决策框架

面试和实际工作都会遇到这个问题,给你一个三问决策法:

1. **需求会不会长大?** 演示/内部小工具/一次性活动 → 低代码;要持续迭代、逻辑会越来越怪 → 写代码(平台的天花板会越来越硌头);
2. **要不要深度集成?** 只需要一个聊天框 → 低代码;要嵌进自己的 App、要改协议、要精细控制流式输出 → 写代码(参考 docs/2 第 4、11 篇);
3. **数据敏不敏感?** 无所谓 → 云平台;敏感 → Dify/FastGPT/n8n 私有化部署,或纯自研。

现实中最常见的成熟做法是**混合**:用低代码平台快速验证需求(一天出原型给老板看),验证通过后用代码重写核心链路(可控、可测、可优化)。原型思维+工程思维,两手都要硬。

---

## 面试视角

1. **"为什么你们不用 Dify 而要自研?"**——答灵活性(自研可以精细控制重试/降级/上下文策略)、可测试性(代码能写单元测试,拖拽流程很难)、成本(量大后平台抽成/托管费超过自研运维成本)。能反过来说清"什么场景我会选 Dify"(快速验证、非核心链路)更显成熟。
2. **"低代码平台的知识库和自研 RAG 有什么区别?"**——本质相同(切块→向量化→检索→增强生成),区别在可调参数的粒度和对检索质量的掌控力。答完顺势引到第八章/docs/2 第 10 篇的 RAG 优化,展示知识纵深。

---

## 划重点

1. 低代码平台=**用灵活性换开发速度**:可视化编排+现成组件+托管运行,天花板是"平台没有的你做不到"。
2. 四平台性格:**Coze 重发布生态,Dify 重工程集成,FastGPT 重知识库问答,n8n 重万物互联**。
3. **Profile/Skills/Rules/Workflows** 结构化提示词模板是本章最值得带走的资产,写代码同样适用。
4. 选型三问:需求会不会长大、要不要深度集成、数据敏不敏感。成熟做法是**低代码验证原型,代码重写核心**。
5. 至少亲手搭完一个案例——拖拽的爽和拖拽的憋屈,都得亲身体会过,选型时才有底气。
